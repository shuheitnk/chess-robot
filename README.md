# chess-robot

あなたとの対局だけで、日々少しずつ強くなるチェスロボット。

小型ロボットアーム **SO-101** が、重力と摩擦のある物理シミュレーション（MuJoCo）の中で、本物の駒をつかんで指します。
頭脳は最初は何も知りません（駒の価値さえ知らない）。あなたと対局するたびに、その結果だけを材料に進化戦略で学び、成長し続けます。

## 2段階の学習

| 段階 | 何を学ぶか | 材料 | 方法 |
| --- | --- | --- | --- |
| 1. 技能の事前学習 | 駒をつかむ・運ぶ・置く動作（8つのパラメータ） | ランダムに駒を並べた盤で「指定の駒を指定のマスへ」 | CMA-ES |
| 2. 戦略の生涯学習 | 盤面の評価の重み（12個の特徴量） | **あなたとの対局だけ** | 対称サンプリングの進化戦略 |
| （夜の練習） | 技能の8つのパラメータの磨き直し | 対局で駒を倒した・ずらした場面＋ランダムな盤 | CMA-ES（良くなったときだけ置き換え） |

### 1. 技能の事前学習（`scripts/pretrain_skill.py`）
「つかむ高さ」「指の開き」「握る強さ」「離すときの開き」「降りる速さ」「運ぶ速さ」「待つ時間」「移動の高さ」を、
ランダムな初期値から CMA-ES で最適化します。毎世代、駒10〜28個をランダムに並べた盤で課題を解かせ、

- 置いた位置のずれ（3mm以内で成功）
- 周りの駒を動かしてしまった量
- 駒が倒れたか
- かかった時間

で評価します。成功率が目標（既定 95%）に届いたら「安定」として `~/.chess-robot/skill.json` に保存し、対局で使えるようになります。

**最初の事前学習の結果（14世代・候補8・各3課題）**：駒24個のランダム配置で12課題を解かせたテストで、
ランダムな初期値も学習後も成功率は100%（置き位置のずれは平均0.2mm）。学習で変わったのは速さで、
1回の移動が平均16.1秒 → 10.6秒になりました（指を大きめに開いて素早く降り、運ぶ時間と待ち時間を短く）。
動作の土台が丈夫なぶん、今の課題では「速くても失敗しない動き」を探す学習になっています。
置き位置のばらつきや駒の向きを大きくするなど、課題を難しくすると、成功率そのものの差が出てくるはずです。

動作そのものの土台（逆運動学、指を真下に向けたまま降りる、周りの駒から指が一番離れる向きを16方向から選ぶ、重力によるたわみの補正）は `chess_robot/robot.py` にあります。

### 2. 戦略の生涯学習（`chess_robot/brain.py`）
- 盤面の評価 ＝ 特徴量 × 重み。特徴量は「ポーン・ナイト・ビショップ・ルーク・クイーンの数の差」「動ける手の数」「中央の支配」「相手キング周りへの圧力」「ポーンの前進」「王手」「駒の展開」「ただで取られる駒」
- 重みは **すべて 0 から始まる**（＝合法手をランダムに指すのと同じ）
- 2手先まで読むアルファベータ探索で手を選ぶ
- 学習：1局目は「重み ＋ σε」、2局目は「重み − σε」で指し、報酬が良かった向きへ重みを動かす
- **報酬 ＝ ゲーム終了時に取った駒の点数 − 取られた駒の点数**（P=1, N=3, B=3, R=5, Q=9）
- 状態は `~/.chess-robot/brain.json`、全対局の記録は `~/.chess-robot/history.jsonl` に残り、日をまたいで育ち続けます

対局の前後に「Day 7 ・ これまでの対局 23 局」「いま大事だと思っていること：クイーン +1.84 …」のように、成長の様子が表示されます。

## 使い方

[uv](https://docs.astral.sh/uv/) を使います。

```bash
uv sync
uv run python scripts/setup_model.py        # SO-101 の公開モデルを取得してシーンを作る
uv run python scripts/pretrain_skill.py     # 技能の事前学習（数十分）
uv run python scripts/play.py               # 対局！ブラウザに KOMA の画面が開く（KOMA＝白、あなた＝黒）
```

### 相棒ロボット「KOMA」の画面

`scripts/play.py` を実行すると、ブラウザに KOMA の画面（`http://127.0.0.1:8765/play`）が開きます。MuJoCo の3Dは今までどおり別ウィンドウです。
画面は PC では3列、スマホの幅では縦に並びます。

- **盤**：あなた（黒）が手前。自分の駒をクリック → 行けるマスに琥珀色のひし形（取れる駒には琥珀色の枠）→ 行き先をクリック。成りは Q/R/B/N の小さなメニュー
- **01 VISION**：盤を真上から写したシミュレーションの画像（数フレーム/秒）と、盤の検出グリッド。指す前と後の画像を比べて、見た目が変わったマスを探し、実際の手と合っているかを表示します（実機ではカメラの映像に差し替える前提）
- **02 ACTUATORS**：6つの関節の角度と負荷（力の上限に対する割合）。温度は実機のときだけ
- **03 COMPANION**：KOMA のひとこと（一人称）、その局面の評価、いま大事だと思っている重みの上位5つ、棋譜、学習の対の何局目か
- **Fix board**（全部の駒を正しいマスに戻す）・**Resign**（投了）・**Quit**（学習しない中断）。終局したら報酬と学習の結果が出て、**Play again** で次の対局へ
- 画面の数字はすべて実際のデータです。データがないときは「—」を表示します

| オプション | 内容 |
| --- | --- |
| `--text` | 物理なしで、同じ画面で指す。たくさん対局して育てたいとき |
| `--cli` | 画面を使わず、ターミナルでキーボード入力（以前の方式。`fix` で駒を直す。`--text --cli` で物理なし） |
| `--lan` | 同じネットワークのスマホからも画面を開けるようにする（家のネットワークだけで使ってください） |
| `--no-viewer` / `--no-browser` | MuJoCo の3Dウィンドウ / ブラウザを開かない |
| `--record game.mp4` | 対局の動画を保存 |

止めるときはターミナルで Ctrl+C。

- `scripts/demo_video.py --out demo.mp4`：ロボットが決まった棋譜を指すデモ動画

### 夜の練習（手先の技能だけを鍛える）

```bash
uv run python scripts/night_practice.py      # 寝る前に。15世代・候補8で1時間前後。ブラウザに練習の画面（/night）が開く
```

- 今の `skill.json` を出発点に、CMA-ES を数世代回します。課題は「対局で倒した・ずらした場面（`practice_cases.jsonl`。まだ解けていない新しいものから最大6つ）」と「ランダムな盤」を混ぜたもので、一晩のあいだ同じ課題を使うので、世代ごとの成功率をそのまま比べられます
- 最後に、練習とは別のテスト課題（場面の駒を ±1mm ずらしたもの＋別のランダムな盤）で今の技能と比べ、**良くなったときだけ** `skill.json` を置き換えます（成功率が上がった、または同じ成功率でコストが2%以上下がった）
- 結果は `night_log.jsonl` に追記し、最後に GitHub と同期します
- **学習の線引き**：夜に鍛えるのは手先の技能だけ。頭脳（評価の重み）は、昼のあなたとの対局だけで学びます
- 画面：成功率のリング（外側＝今、内側＝練習前）、世代の進み、世代ごとの成功率、練習中の場面（SOLVED / PRACTICING / QUEUED）、今いちばん良いパラメータ8つと変化量。練習が終わったあとは、`play.py` の画面の Night からも最後の結果を見られます
- オプション：`--gens`（世代数）、`--popsize`（候補の数）、`--cases`（一晩の場面の数）、`--random`（混ぜるランダムな盤）、`--workers`（並列の数）

### 育てたデータの保存場所

技能・頭脳・対局の記録は、リポジトリの外の `~/.chess-robot/`（Windows なら `C:\Users\<ユーザ名>\.chess-robot\`）に保存されます。
リポジトリを消したりクローンし直したりしても、頭脳はそのまま残ります。

| ファイル | 中身 | 消すと |
| --- | --- | --- |
| `brain.json` | 頭脳（評価の重み・対局数） | 生まれたての状態に戻る |
| `history.jsonl` | 全対局の記録（棋譜・報酬・その時の重み） | 記録だけ消える（強さは変わらない） |
| `skill.json` | 駒を動かす技能 | 事前学習をやり直す必要がある |
| `practice_cases.jsonl` | ロボットが駒を倒した・ずらした場面（直前の駒の配置・指した手・ずれの量）。夜の練習の教材 | 練習する場面がなくなる |
| `night_log.jsonl` | 夜の練習の記録（世代ごとの成功率・場面の結果・テスト・置き換えたか） | 記録だけ消える（技能は変わらない） |

別の場所に置きたいときは、環境変数 `CHESS_ROBOT_DATA` にフォルダを指定します（Google Drive などの同期フォルダにすれば、別の PC でも同じ頭脳を育てられます）。
以前の版でリポジトリの中の `data/` に保存していたファイルは、初回の起動時に自動で移されます。

### 脳を GitHub で持ち運ぶ（別の PC で続きを指す）

GitHub で空のリポジトリ（例：`chess-robot-brain`、非公開がおすすめ）を作り、それぞれの PC で1回だけつなぎます。

```bash
uv run python scripts/sync.py init https://github.com/<ユーザ名>/chess-robot-brain.git
```

あとは `scripts/play.py` が、対局の前に GitHub の脳を取ってきて、対局の後に送ります（`--no-sync` で止められます）。
技能（`skill.json`）も一緒に運ばれるので、事前学習は1台でやれば十分です。

- 手動で同期：`scripts/sync.py pull` / `scripts/sync.py push`、状態の確認：`scripts/sync.py status`
- オフラインのときは同期をとばして、その PC に保存します。次の対局のときに送ります
- 2台で同期せずに別々に育ててしまったときは、頭脳は対局数の多いほうを残し、対局の記録は両方をまとめます

キーボードで入力するとき（`--cli`）は、`e5` `Nf6` のような棋譜表記か `e7e5` の形式。同じマスへ行ける駒が2つあるときは `Nge6`（g列のナイト）や `R1e6`（1段目のルーク）のように元の列か段を足すか、`g5e6` のように元のマスから書きます（`Ne6` だけだと候補が表示されます）。駒を取る手は `Bxg7` のように `x` を入れます（`Bg7` でも通ります）。マスだけ（`g7`）はポーンの手と読まれますが、ポーンで行けないときはそのマスへ行ける手が表示されます。

Windows では盤面を文字で表示します（大文字＝ロボット、小文字＝あなた。K キング・Q クイーン・R ルーク・B ビショップ・N ナイト・P ポーン）。駒の記号で見たいときは `--unicode`。`resign`（投了）、`quit`（学習せずに中断）、`help`（合法手の一覧）、`fix`（駒を直す、3D のみ）。

## 見た目

- 駒：スタントン型。断面を回転させた回転体のメッシュ（ナイトは横顔を丸く押し出した形）。象牙色と黒檀色の光沢素材
- 盤：メープルとウォールナットのマス、真鍮の縁取り、つやのある枠
- アーム：白い外装と黒いサーボ。高さ3cmの台に載せ、暗い背景に3灯の照明

## シミュレーション上の工夫と割り切り

- 駒の衝突形状は「台座（半径6.5mm・高さ8mm）＋細い胴体」。アームは台座をつかむ
- 指先には摩擦の大きいパッドを付け、指の力は弱めに設定（実機ではトルク上限で設定できる）
- アームの各リンクに重力補償を入れて、位置制御のたわみを抑えている
- 公開モデルの衝突形状は凸包で実物より太いため、アームを折りたたんだときの見かけ上の自己衝突は除外している
- あなたの手は「見えない手」が駒を運ぶ（物理ではなく位置を直接動かす）
- ポーンが成っても、シミュレーション上の駒の形はポーンのまま（盤の状態は正しく成る）
- ロボットは指し終えたら、肩を横に回した待機姿勢に戻る（盤の上を空けて、真上のカメラと人の手の邪魔をしない）
- ロボットが駒を1つ運ぶたびに、置き位置のずれ（3mm）・周りの駒を動かした量（合計3mm）・倒れ（傾き10°以上、または盤から2mm以上の浮き沈み。傾きはクォータニオンから出る駒の上向きの軸で判定）を調べる。うまくいかなかったら、その場面を `practice_cases.jsonl` に記録する
- ロボットが指すたびに、2mm以上ずれた駒と倒れた駒を正しいマスへ戻してから対局を続ける

## テスト

```bash
uv run python tests/test_web_play.py --text   # 画面のサーバを立ち上げ、WebSocket で数手指す（物理なし・速い）
uv run python tests/test_web_play.py          # 同じことを物理シミュレーションありで（数分）
uv run python tests/test_practice_cases.py    # 倒れ・ずれの判定と直し、失敗した場面の記録と再現
uv run python tests/test_night.py             # 夜の練習を短く回す（2世代・候補4。数分）
```

テストは一時フォルダをデータの場所にして動くので、育てた脳（`~/.chess-robot`）は変わりません。

## クレジット

SO-101 のモデルは [TheRobotStudio/SO-ARM100](https://github.com/TheRobotStudio/SO-ARM100)（Apache-2.0）のものを、`scripts/setup_model.py` で取得して使っています。
